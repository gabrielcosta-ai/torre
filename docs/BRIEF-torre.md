## O que é a Torre
Painel de controle do Gabriel para o sistema de agentes (Maestri): ele aprova/reprova pendências (GO, Não, Feito, opção A/B com justificativa), deixa nota, pede explicação e recebe resposta, fala com o maestro; vê as frentes (operador, marco atual → próximo, recrutas, TRAVADO/RISCO), tokens (cotas por balde, sessões em excesso, totais por modelo, custo por frente) e memória (fatos do acervo, quebrados, gotchas por projeto = onde os agentes falham por repo). Agentes (sessões Claude no Mac, na nuvem, Cursor, servidor) gravam e leem por API HTTP com token. Referência visual e de comportamento JÁ PRONTA: `reference/torre.html (neste repo)` (leia inteiro: tokens de tema, 5 blocos, cartões, tabelas, gráfico SVG de gotchas, formatação pt-BR). Porte esse visual e essa lógica de tela; troque a fonte de dados (era `claude.use("db")`) por fetch à API própria com polling de 15 s. Aplique também os 2 itens "Bloqueia publicar" de `reference/torre-revisao.md` (erro de gravação sumia sem aviso).

## Stack (fixa)
- Next.js 15 (App Router, TypeScript, `src/`), sem Tailwind: CSS puro com os tokens do torre.html em `globals.css` (claro + `prefers-color-scheme: dark` + `[data-theme]`). Fontes IBM Plex via `next/font/google`. Sem emoji. Funciona a 400 px sem scroll horizontal da página.
- Banco: Postgres via Neon (integração Vercel Storage; env `DATABASE_URL`/`POSTGRES_URL` injetada pela Vercel). Cliente `@neondatabase/serverless` ou `postgres` (porsager). Migração em `db/schema.sql` idempotente (`create table if not exists`) aplicada por `npm run db:migrate` (script Node que lê `DATABASE_URL`).
- Auth do Gabriel: **passkeys (WebAuthn)**, uma por dispositivo (celular, PC) = "chave por aparelho". Lib `@simplewebauthn/server` + `@simplewebauthn/browser`. Fluxo: (1) primeiro cadastro em `/entrar` exige `TORRE_SETUP_CODE` (env, uso único: após o 1º cadastro o servidor grava `setup_usado=true` em `config`); (2) aparelho novo: de um aparelho já logado, botão "Adicionar aparelho" gera código de 6 dígitos válido por 10 min (tabela `convites`); o novo aparelho digita o código em `/entrar` e registra a passkey. Sessão = cookie HttpOnly/Secure/SameSite=Lax com JWT (`TORRE_SESSION_SECRET`), 30 dias. `rpID` = host da env `TORRE_HOST` (ex.: `torre.vercel.app`); `origin` = `https://${TORRE_HOST}`. Login com Google fica FORA da v2 (anotar como fase 3).
- Auth dos agentes: header `Authorization: Bearer ${TORRE_AGENT_TOKEN}` (env). Só rotas `/api/*`. Toda rota valida um dos dois (cookie ou bearer); nada é público além de `/entrar` e `/api/saude`.
- Sem dependência de claude.ai. Sem analytics. Sem `confirm()`.

## Modelo de dados (tabelas; `id text primary key` quando o agente escolhe o id)
- `pendentes` {id, titulo, tipo GO|DECISAO|COMANDO|LOGIN|UI, frente, quem_pediu, destrava, comandos jsonb (string[]), opcoes jsonb ([{id,texto,justificativa}]), criado_em timestamptz, status aberto|go|nao|feito|opcao:<id>, resposta, respondido_em}
- `frentes` {nome pk, operador, modelo, marco_atual, proximo_marco, travado, risco, recrutas jsonb ([{nome,modelo,effort}]), atualizado_em}
- `custo` {id pk (frente+periodo), frente, periodo, tokens_in, tokens_out, cache_read, usd_estimado numeric, atualizado_em}
- `sessoes` {sessao_id pk, conta, projeto, modelo, papel, tokens_out, cache_read, cache_create, tokens_in, turnos, ultimo_turno, alerta bool, atualizado_em}
- `cotas` {id pk (conta-balde), conta, balde, usado_pct numeric, renova_em, medido_em}
- `memoria` {id pk = 'atual', fatos_total, fatos_quebrados, por_projeto jsonb, ultimos jsonb ([{name,description,modified}]), gotchas_7d_por_projeto jsonb, medido_em}
- `mensagens` {id serial, pendente_id null, de gabriel|maestro|<agente>, texto, criado_em, lida_em} — thread por pendência ("Pedir explicação") e thread geral (`pendente_id null`, "Falar com o maestro").
- `passkeys`, `convites`, `config` (setup_usado).

## API (JSON; `PUT` = upsert; erros `{erro}` com 400/401/404)
`GET /api/saude` → `{ok:true}` (público). `GET/POST /api/pendentes`, `PATCH /api/pendentes/:id` (status/resposta/respondido_em pela UI; qualquer campo pelo agente). `GET /api/frentes`, `PUT /api/frentes/:nome`. `GET /api/custo`, `PUT /api/custo`. `GET /api/sessoes`, `PUT /api/sessoes` (array, upsert em lote). `GET/PUT /api/cotas` (array). `GET/PUT /api/memoria`. `GET /api/mensagens?desde=<iso>&nao_lidas=1`, `POST /api/mensagens`, `PATCH /api/mensagens/:id` (lida_em). `GET /api/resumo` → tudo que a tela precisa numa chamada (a UI usa só esta com polling 15 s + revalida após cada ação). Também `GET /api/auth/registro/opcoes`, `POST /api/auth/registro`, `GET /api/auth/login/opcoes`, `POST /api/auth/login`, `POST /api/auth/sair`, `POST /api/auth/convite`.

## Tela (igual ao torre.html, mais)
Cabeçalho (Torre · N abertos · atualizado há X · "Falar com o maestro" · "Adicionar aparelho" · Sair). Pendentes (abertos em cartões com ações e nota; "Pedir explicação" abre a thread do item inline: lista de `mensagens` + campo de texto; fechados recolhidos com Reabrir). Frentes. Tokens (cotas, sessões em excesso, totais por modelo, custo por frente). Memória (KPIs, gráfico gotchas, últimos 10). Mensagens do maestro não lidas aparecem em destaque no topo da thread.
